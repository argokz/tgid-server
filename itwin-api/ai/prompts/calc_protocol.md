Задача: объяснить протокол гидравлического расчёта тепловой сети (расчётная программа sety) и подсказать, что исправить.

Во входе: заголовок протокола (база, фрагмент, режим, температура наружного воздуха Tн), параметры запуска, сводка по категориям и сами сообщения (ошибки и предупреждения) с объектами сети. Сообщения уже сгруппированы по категориям; у многих категорий есть «fix» — какой инструмент веба открыть для исправления:
- calc_params — параметры расчёта (окно запуска);
- fixed_head — узел с заданным напором (карточка узла → гидравлика);
- temp_graph — температурный график источника;
- rs — справочник расчётных схем (РС);
- object — карточка объекта из сообщения (узел, участок, регулятор, потребитель).

Как рассуждать:
1. Сначала ошибки (расчёт не выполнен, подсети без узла с ЗН, нет данных) — это корневые причины, без них результата нет.
2. Предупреждения регуляторов: «Задано X м, получено Y м, расход Z т/ч». Если получено меньше заданного при открытом клапане — не хватает напора (источник/насос/диаметр), если больше — регулятор закрыт до предела или уставка ниже возможной; одинаковые симптомы у соседних регуляторов — одна причина выше по сети.
3. Напоры у потребителей меньше высоты здания, отрицательные перепады — последствия, а не причины, если есть ошибки выше.
4. Повторяющиеся сообщения (count > 1) — одно и то же по итерациям, не умножай их.

Ответ (JSON по схеме):
- summary — 2–4 предложения для инженера: сошёлся ли расчёт, главная причина, что делать в первую очередь.
- root_causes — 1–6 причин, от главной к второстепенным: category (из входа), title (коротко), why (почему так, со ссылкой на числа из входа), action (что сделать), fix (один из calc_params|fixed_head|temp_graph|rs|object или null), objects — объекты из входа, к которым относится причина (только их id/kind/label).
- regulators_note — общий вывод по регуляторам давления/расхода, если они есть во входе, иначе пустая строка.
- next_run — какие флаги запуска имеет смысл попробовать и зачем (только из списка: -Tn, -iter, -no_kv, -rd_old, -rr_old, -ok_old, -tg, -leto, -dross_yes, -mag_fragment); пустой список, если менять нечего.
- data_quality — замечания к исходным данным (нули, пропуски, несогласованные коды), если видны во входе.
