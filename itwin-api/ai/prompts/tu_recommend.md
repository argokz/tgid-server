Задача: по заявке на технические условия (ТУ) подключения нового потребителя выбрать точку подключения к тепловой сети и подготовить черновик полей ТУ.

Во входе:
- текст заявки (может быть неполным): адрес, назначение объекта, этажность, площадь, запрошенная нагрузка;
- оценка нагрузки по аналогам (если этажность известна);
- кандидаты точек подключения, уже ранжированные кодом: узел (камера), расстояние, участок (диаметр, год прокладки), режим по последнему расчёту (напоры подачи/обратки, располагаемый напор, скорость до и после подключения, расход), источник, балл и причины. Пороги: скорость 1,5–3,5 м/с, располагаемый напор не меньше 15 м.

Как рассуждать:
1. Если запрошенная нагрузка не указана — используй оценку по аналогам и скажи об этом в risks.
2. Выбирай кандидата по совокупности: запас по скорости и напору важнее близости; участок без расчёта — только если нет других и с оговоркой.
3. Если все кандидаты перегружены или без напора — chosen_index = null, объясни и предложи, что проверить (расчёт фрагмента, другой источник, увеличение радиуса).
4. Прирост по видам нагрузки распредели по назначению объекта: жильё — отопление ~60 %, ГВС ~40 %; офис/торговля — отопление ~55 %, вентиляция ~35 %, ГВС ~10 %; производство — по заявке. Если в заявке даны доли — бери их.

Ответ (JSON по схеме):
- request: разобранная заявка (address, purpose, floors, area_m2, load_gcal_h) — null там, где не сказано;
- chosen_index — индекс выбранного кандидата из входа (0-based) или null;
- explanation — 2–4 предложения для инженера, с числами из входа;
- alternatives — другие приемлемые кандидаты с короткой оговоркой;
- draft — черновик полей ТУ: istochnik (имя источника из входа), kamera (имя узла из входа), prirost_nagruzki и его разбивка otoplenie/ventilyatsiya/gvs (Гкал/ч, сумма = прирост);
- risks — что проверить перед выдачей ТУ.
