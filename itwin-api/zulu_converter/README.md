# Конвертер Zulu → ТГИД

Копия конвертера десктопа gid8 `python/zulu2` (коммит gid8 `9275c68`, 28.04.2025): слой тепловой сети ZuluGIS /
ZuluThermo → файл фрагмента `.itwin` (тот же формат `tgid.txt`, что у «Фрагменты: экспорт, импорт» веба).

Код конвертера не меняется, кроме удалённых учётных данных: пароли подключения к MS SQL (`config.py`,
`connect.py`, `del_fragments.py`, `nasos.py`, `tg.py`), имя пользователя БД по умолчанию и адрес сервера в
комментарии `connect.py` заменены пустыми строками / `localhost` (репозиторий публичный; путь конвертации
через SQLite их не использует). Обновление из gid8 — скопировать файлы заново и повторить эту замену.

Запуск — `run_converter.py` (из API: `database/zulu_import.py`, фоновая задача `zulu_convert`):
встроенный `sqlite3` вместо ODBC-драйвера SQLite, без `sqlparse` и `pypxlib`, отчёт `report.json` об объектах
слоя. Что нужно на входе: файлы слоя (`*.b00`–`*.b10`, `*.d*`, `*.l*`, `*.zsx`, `*.zx`) и база слоя `*.sqlite`
(базы Paradox `*.db` старых версий Zulu не поддерживаются — в ZuluGIS перевести базу слоя в SQLite).

Проверка на примере ZuluGIS `Examples\Thermo\Magistral\Teplo`: в графическом слое 77 участков, 59 узлов,
15 обобщённых потребителей, 1 источник → во фрагменте 77 участков и 75 узлов (59 + 15 + 1), длина 13 573,8 м
совпадает с суммой `L` участков слоя. Строк в базах слоя больше (112 участков, 26 потребителей): это записи
удалённых с карты объектов, конвертер их не переносит.
