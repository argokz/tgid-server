## 1. Ошибки в рабочем коде (высокий приоритет)

### 1.1. `read_tg.py` → `get_tg`: неверная интерполяция температурного графика
Функция вызывается почти везде (consumption, otopl, teplo1, y_ut, zt, pt_out*, read_gid).
- Последний отрезок: в конце цикла `tn0 = tn` (температура запроса) вместо `tn0 = tn1`.
  В ветке последней точки множитель `(tn - tn0)` всегда 0 — между двумя последними точками графика
  возвращается значение последней точки без интерполяции.
- Для `tn` между точками `tn0` и `tn1` берется наклон **следующего** отрезка `[tn1, tn2]`
  (экстраполяция назад), а не отрезка `[tn0, tn1]` — на изломе графика будет ошибка.
- Нет деления на шаг: `t1_1 + (t1_2 - t1_1)*(tn - tn1)` верно только при шаге таблицы ровно 1 °C;
  первая точка графика (например −31.8) дает шаг 0.8.
- При `tn` выше последней точки возвращается `None` (в `consumption_tg` для ГВС `sm` это не
  проверяется — будет TypeError).

### 1.2. `teplo/teplo1.py` → `init_matrix_teplo`, ветка `TO` (typTO == 11)
Внутренний цикл `for k, (n1, n2, key) in edges_nIin0:` использует те же имена `n1, n2, key, l, l_typ, k_l`,
что и внешний цикл по ветвям узла. После него `QQ = l.get('ZZ', 0)` берет нагрузку с **последней ветви
узла nIn**, а не с теплообменника. Влияет на тепловой расчет ГВС II ступени во внутренних схемах.

### 1.3. `g2.py` → `make_G2` (суммирование нагрузок для обобщенных потребителей)
- `isEl` вычисляется по схеме, но затем строка `otop, vent, gv, rez, isEl = '', '', '', '', False`
  затирает его **до** вызова `num(otopln, otoplz, isEl)` — код схемы `cx` никогда не бывает 1
  (элеваторная), все зависимые схемы получают 2.
- В `itog2` записываются ключи `'Tr_tv_zco'`, `'Tr_tv_nco'`, `'Tr_gvs_'`, а читаются
  `'Tr_tv_co_zco'`, `'Tr_tv_co_nco'`, `'Tr_gvs_oo_op'` — в результат всегда уходят значения
  по умолчанию 18 и 60, а не температуры потребителей.

### 1.4. `teplo/rasto_po.py` → `rasTO_po`: кондиционирование
`Qkond1 += qq_v / 1e6` — для кондиционирования суммируется тепло **вентиляции** (`qq_v` вместо `qq_k`).

### 1.5. `out/pt_out.py` → `make_sql_potr`: затирание сопротивления обратки
```
hydroResWDORet = case when calcSignResWDORetID <> 2 then t.s3
else hydroResWDOFlow   -- должно быть hydroResWDORet
```
Если у потребителя стоит признак «не пересчитывать» (2), его сопротивление обратки перезаписывается
значением подачи. Ошибка в обоих вариантах запроса (PostgreSQL и MS SQL).

### 1.6. `out/pt_out3.py` → `out_PT_OUT3`: опечатка в условии
`if abs(GP) < 1e-8 and abs(GO):` — пропущено `< 1e-8` (в `pt_out.py`: `abs(GP) < 1e-8 and abs(GO) < 1e-8`).
Пропускаются потребители с нулевой подачей и **ненулевой** обраткой, а с обоими нулевыми — нет.

### 1.7. `out/pt_out*.py`: фактическая нагрузка
- `Qfact` и `Qsum_z` считаются только при `Qotopl > 0`: у потребителей без отопления и во всех
  потребителях летом `Qfact = 0`, `Qsum_z = NULL`, хотя ГВС есть.
- В `pt_out2.py` `Qfact` не инициализируется вообще — NameError или значение предыдущего потребителя.
- В `out_PT_OUT`/`out_PT_OUT2`: если `consumption.type_of_cons(cxema)` вернул `None` (нераспознанная
  схема), `Qotoplz`/`Qotopln` не присваиваются и берутся от **предыдущего** потребителя.
- В `pt_out2.py`, `pt_out3.py` `ut = (tv1 - tv3) / (tv3 - tv2)` без проверки `tv3 == tv2`
  (в `pt_out.py` проверка есть).

### 1.8. `read_gid.py` → `read_node2`: запись в чужой узел
В блоке обратки (`externalSignID in (1, 3)`) стоит `nP['Qz'] = Qz` (копипаст, должно быть `nO`).
Для узла только с обраткой (`externalSignID == 3`) переменная `nP` в этой итерации не присвоена —
запись идет в узел **предыдущей строки** (то же для `nP['id2'] = id2` ниже) или падает в голый `except`.

### 1.9. `read_vnutr.py` → `read_pt_vnutr` (внутренние схемы потребителей, детализированный расчет)
- Ключи ребер `key=(id, 1)`, `(id, 5)`, `(id, 6)`: `id` здесь — **встроенная функция Python**
  (локальной переменной нет). Все внутренние ветви между одной парой узлов получают одинаковый ключ,
  и параллельная ветвь в `MultiDiGraph` затирает предыдущую.
- Словарь `ut` один на все ветви схемы и передается через `**ut`: поля прошлых элементов
  (`'ZZ'`, `'typ_gvs'`, `'typTO'`) «протекают» в следующие ветви, где они не задаются.
- Проверка `if cxema is None` стоит **после** циклов `for line in cxema` — при отсутствии схемы будет
  TypeError вместо сообщения «Не задана внутренняя схема».
- `from consumption import get_pt_name` — импорт не через пакет (см. п. 5).

### 1.10. `dross/z_dross.py` → `dross`: тип схемы в DR_OUT
Тип определяется посимвольно (`cxema[0]`, `cxema[2]`). Для двузначных номеров это неверно:
`'15.x'` и `'100.1'` попадают в «Зав.СО/Нез.СО» (ветка `cxema[0] == '15'` недостижима),
`'3.10'…'7.12'` дают `cxema[2] == '1'` → «ЗСО» вместо «НСО». В `b5.txt` такие схемы есть.

### 1.11. Дросселирование (`-dross_yes`): падения
- `dross/drvary3.py`: вызывается `drvary1`, который **не импортирован** → NameError; к тому же в вызове
  пропущен аргумент `Gz` (все аргументы сдвинуты). Срабатывает при признаке ступени 3 и недостаточном напоре.
- `dross/drvary4.py`: `return ferr` — `ferr` не определен, если `ggv > 0` или `hrc <= 0` → UnboundLocalError.
- `dross/drvary3.py`: `ferr` может остаться неопределенным к `return`.
- `dross/z_dross.py`: результат `drvary1..5` игнорируется — функция возвращает `True` даже при ошибке.

### 1.12. `out/Qtreb.py` → `write_Qtreb_po`: параметр `-GWS2` не работает для обобщенных потребителей
Результат выбора по `config.args.GWS2` сразу перезаписывается `koef = 1`, `koef_rez = 0.85`
(в `write_Qtreb` для реальных — учитывается).

### 1.13. `teplo/y_ut.py` → `get_q_new`: участки большого диаметра останавливают расчет
Если диаметр больше максимального в справочнике 39 (1400–1480 мм; для периода 1998–2003 и надземной
прокладки — 1000 мм), цикл не делает `break`, `d2 == d1` → деление на ноль. В `norma` исключение
перехватывается, но затем `return qq` с неопределенным `qq` → UnboundLocalError → в
`read_gid.read_line_row` «Что-то с нормами тепловых потерь» и `exit(1)` для всего расчета.
Для периода до 1990 берется диаметр с изоляцией (`diametr + 2*tol`) — его легко превысить.

### 1.14. `consumption.py` → рециркуляция и `fatal_error`
- `fatal_error()` печатает неопределенную переменную `p` → NameError.
- В `consumption_tg`: `G_rez = ... / t_ost` считается **до** проверки `t_ost <= 0`
  (при `t_ost == 0` — ZeroDivisionError), а при `t_ost < 0` вызывается `fatal_error` → NameError;
  поясняющие сообщения после него не печатаются.

### 1.15. Прочие падения в рабочих ветках
- `read_gid2.py` → `read_BP`: если `nodeID >= 0`, но узел не найден в графе, `Z` не определен →
  UnboundLocalError.
- `teplo/tepl_vent.py` → `rasVENT`: вызывается `fatal_error()`, который не импортирован → NameError
  вместо сообщения «Не создан объект "Расчетные температуры"».
- `w_out.py` → `set_G_out`, ветка `realConsumers`: `S2 = (h1-h2)/r/r` без проверки `r == 0`
  (а `S2` даже не используется).
- `w.py` → `run`: `ff_str = '.'.join(...)` — фрагменты соединяются **точкой**: при нескольких
  fileID получится `in (1.2)`. Сейчас передается один фрагмент.
- `teplo/f.py` → `getFp`: если для ступени нет подходящей схемы ГВС, — `print(pr)` и `exit(1)` для
  всего расчета из-за одного потребителя.

## 2. Подозрительные места — проверить на данных

1. **`read_db.py` → `read_row`, `read_row2`: `if v:` отбрасывает 0, 0.0, '' и False.**
   Нулевые значения из БД не попадают в словарь, и дальше срабатывают значения по умолчанию из
   `.get(key, default)`: например, `pr.get('Tr_gvs', 60)`, `pr.get('a7', 1.5)` в dross1 и т.п.
   Ноль в БД молча превращается в «умолчание».
2. **`consumption.py` → `set_kv`: коэффициенты вариации по умолчанию 0.** `kv.get('otoplz', 0)` и т.д.:
   если коэффициент для вида нагрузки не заполнен (или он 0 и отброшен по п. 1), нагрузка
   **умножается на 0**. По смыслу умолчание должно быть 1.
3. **«Поправка на подпитку» температуры:** `out/us_out.py` → `t = -t*Gout/Gin`;
   `out/out_teplo.py` → `protocol_IS_OUT` и `out/is_out.py` → `t2_ispr *= Gin_P/Gin_O`.
   Температура умножается на отношение расходов — физический смысл сомнителен.
4. **`w_calc.py` → `proverka`, `regulArmatures`:** сравнивается `r1` с `(h2 - h1)`, а уравнение
   в `make_matrix` задает `h1 - h2 = r1*sign(G)`. При прямом потоке будет ложное
   предупреждение «Перепад задано/получено». Проверить знак.
5. **`sopr_ut.py` → `reset_sopr`:** параметр `heatSourceID`, если пришел `None`, берется из расчетной
   схемы **первого** участка и дальше используется для всех участков (параметр перезаписывается
   в цикле) — температуры для остальных участков могут быть от чужого источника.
6. **`teplo/tepl_gws1ps.py`:** в `getE1` формула `dGbo` отличается от `getF1` (`Tx` вместо `delta_tg_ps`) —
   похоже на опечатку. В одной функции разные умолчания для одной величины: `tr.get('Tx', 18)`,
   `('Tx', 5)`, `('Tx', 0)`.
7. **`dross/drvary5.py`:** две формулы `hrc` подряд, первая (с `a7`) сразу перезаписана — какая верна?
8. **`teplo/y_ut.py`:**
   - в `norma` выбор температуры по `-trtp` сразу перезаписывается `Tn = t_or` — параметр не работает;
   - строки справочника 39 предполагаются отсортированными по диаметру, но `sprav.read_tab_s39`
     читает `SELECT * ...` без `ORDER BY`;
   - при отсутствии таблицы возвращается «магическое» 300 для каждого участка.
9. **`w_out.py`:**
   - в `set_RD_out` стоит `delta0 = 1  #!!! Для отладки!!!`: заданная точность регулятора игнорируется;
   - в `set_HC_out` перегруз насоса с заданным напором (`h > 0`, тогда `a3 = 0`) не определяется никогда.
10. **`w_print.py` → `node_names`:**
    - для внутреннего узла `id` заменяется на id родителя — ссылка ведет на родителя (намеренно ли?);
    - после `setG` переданный `G` игнорируется.
11. **`config.py` → `get_args_json`:** в списке `allowed` есть имена, которых нет среди аргументов
    (`n_GWS`, `n_GWS2`, `is_kv`, `Month`, `n_nagr`, `Eps`, `veter`), а реальные `GWS`, `GWS2`, `no_kv`, `sopr`,
    `is_plan` в `calculation.calc_params` не сохраняются.
12. **Регуляризация `DIAG_REG = 1e-6`** (`calc_nagr.py`, `teplo/teplo1.py`) добавляется к диагонали
    **каждой** строки, а не только вырожденных — решение слегка смещается всегда.
13. **`teplo/teplo1.py` → `calc_teplo`:**
    - ровно 5 итераций без проверки сходимости;

  - величины `QQ` и `qq_*` считаются, но не используются.
- `teplo/potreb.py` → `potreb1` (~1.5 млн вызовов за расчет): считается «линеаризованный» вариант
  (`ttvn`, `tt2`, `qq`), который не используется.
- `teplo/tepl_co1.py` → `rasTT2`: в конце считаются `tv2, T3, G1, F0, q3, q4` (с `pow`) — не используются.
- `w_calc.py` → `solve_G`:
  - на каждой итерации Ньютона считается `beta1 = matrix @ root`, который не используется;
  - печать каждой итерации в stderr.
- `check_ist3.py` → `mark_flow_edges`: `queue.pop(0)` дает O(n²); лучше `collections.deque`.
- `g2.py` → `make_G2`: `nx.multi_source_dijkstra` считается дважды одинаково.
- `line_poteri.py`: `getLinePoteri` вызывается повторно «для отладки».

## 5. Общие проблемы качества кода

- **`exit(1)` из глубины библиотечных функций** (больше 50 мест): одна ошибка в данных одного
  потребителя или участка останавливает весь расчет без возможности обработки. Часть мест печатает
  сообщение после `exit` или не печатает ничего.
- **Дублирование:**
  - `out/pt_out.py`, `pt_out2.py`, `pt_out3.py` — три почти одинаковые функции по ~500 строк, которые
    уже разошлись (п. 1.6, 1.7);
  - `n_ras` — 5 разных функций с одним именем и разными сигнатурами (podpitka, us_out, pt_out,
    pt_out2, pt_out3);
  - две разные `check_ist` (`check_ist.py` и `w_calc.py`);
  - `tg.py` — копия `read_tg.py`, к тому же затеняется пакетом `tg/`;
  - `sprav.read_tab_s39`/`read_csv_s39`.
- **Импорты не через пакет** (`import consumption`, `from consumption import ...`,
  `from check_ec_hs import ...`, `import config` в `teplo2.py`): работают, только если каталог `sety` есть
  в `sys.path`, и модуль загружается дважды под разными именами — две копии глобальных
  словарей. Плюс циклический импорт `consumption ↔ read_gid`.
- **Глобальное состояние:** `read_gid.s_fileID` (с отладочным значением `'3151'` по умолчанию),
  `map_*`, `read_zn.ec_ist` (не очищается между вызовами), `potreb.t01..tn1`, `atm.ATMOSPHERE`,
  `w_print.G_main`.
- **`typ in ('строка')` вместо кортежа** — проверка подстроки, а не равенства: `bp_out.py` (`'bypass'`),
  `dross1.py` (`'realConsumers'`), `pt_out*.py`, `pt_out3.py` (`'realConsumers3'`), `teplo1.py` (`'VN'`, `'TO'`),
  `w_calc.proverka` (`'heatPipeSections'`). Сейчас работает случайно; например, в `bp_out` совпадет и `''`.
  В `rs_out.py` пустой тип `''` явно включен в список.
- **Встроенное имя `id`** используется как ключ, хотя переменной нет: `read_vnutr.py`,
  `read_gid.read_pt_line`. Встроенная `any` затеняется в `w.py` (`from sety.any import any`).
- **SQL собирается f-строками и конкатенацией**, экранируется только апостроф (`insert2`, `write_po`;
  в `make_G2_leto` не экранируется вовсе — апостроф в имени узла ломает запрос).
- **Голые `except:`** (`read_gid`, `sopr`, `consumption.type_of_cons`, `is_bezelevator`, `is_rez`) скрывают
  настоящие ошибки.
- **Мусор отладки в рабочем коде:**
  - проверки по конкретным именам (`'222/185453'` с печатью, `'Тестовый'`, `'7АБ-1'`, `'9-28'`,
    `"4-18 fdhfgjhfgА34534"`, диаметр `990.4` с печатью, `dlina == 100000000`);
  - `if ii == 2 or True`, `and False`, `if True or c is None`;
  - большие блоки старого кода в строковых литералах `'''...'''`.
- **Повторяющиеся ключи в словарях-литералах** (`w_data.py`; Python молча берет последнее значение):
  - `tab_list['generalizedConsumers']`;
  - `'name'` в словаре колонок источника;
  - `'begin_year'`/`'end_year'`;
  - в `map_tn` — `'heatSources'`, `'pumpStations'`, `'nodes'`, `'standardPressRegulators'`
    (в сообщениях печатается «Источник тепла2», «Насосная станция2»);
  - `config.get_args_json`: `'uf_calc'` в множестве дважды.
- **Входные и выходные данные в одних атрибутах графа:** `w_out.set_*_out` пишут результаты
  в `a7..a21` ребер — там же лежат исходные данные (например, `a7`/`a8` участка).
- **Требуется Python 3.12+:** вложенные одинаковые кавычки в f-строках (`teplo/zt.py`, `potreb.py`,
  `safe_spsolvefile.py`, `consumption.py`).
- **`any/colors.py` → `cprint`:** объекты печатаются дважды и не дублируются только потому, что
  `objects` — исчерпанный итератор `map`. Замена на список даст двойной вывод. В HTML-режиме
  теги `u`/`i` некорректны, `blink`/`reverse` — ANSI-коды.
- **Неиспользуемые переменные и импорты** — почти в каждом модуле `out/`: двойной `import networkx`,
  `np`, `logging`, `const`, `sopr`, `db2`, `print_bal`.

## 6. Мелочи по файлам

- `any/db2.py` → `print_q`: перевод строки печатается в stdout, а не в файл `f`;
  `if not cursor.execute(q)` — всегда ложно.
- `any/connect.py`: при пустом пароле порт MS SQL игнорируется; `HandleHierarchyId` всегда возвращает `'0'`.
- `b5/b5.py`: строки не из 11 полей (например, с запятой в имени) молча пропускаются.
- `check_ist.py`: ничего не возвращает, в отличие от `check_ec_hs`.
- `out/is_out.py` → `out_IS_OUT`: считает `G0`, `Q0`, но никуда не пишет — видимо, не доделано.
- `out/out_teplo.py` → `protocol_podpitka`: вся печать закомментирована — функция ничего не делает
  (и опечатка `firrst`).
- `out/protocol_pt.py`:
  - кондиционирование читается, но не входит в итоги;
  - `nO` может быть `None`.
- `out/ok_out.py`: `sost` пишется без значения.
- `out/zd_out.py`: заполняется только `a9`.
- `out/ns_out.py`: состояние всегда «открыт».
- `out/bp_out.py`: колонка `a12` не заполняется.
- `out/ut_out.py`: `if t1 and t2` — температура 0 считается отсутствующей.
- `teplo/otopl.py`: в летнем режиме возвращается `tv = 0`, в других ранних выходах `tv = Tn`.
- `teplo/potreb.py`:
  - при неудаче метода Ньютона `potreb1` делает `exit(1)`, а `potreb2` — намеренное `1/0`;
  - `funcd1` при `xx <= 0` возвращает 0 и 1 соответственно;
  - порядок результата `potreb2` `(q, t3, t2, tv)` запутан.
- `teplo/f.py`: `N_GWS` всегда 4 — ветки 1–3 в `getQ` мертвые, ветки 3 и 4 одинаковые.
- `teplo/tepl_gws2ps.py`: `while True` без ограничения числа итераций, деление на `QIn`.
- `tg/tg_h.py`: `GDN`/`GDK = datetime.now()` вычисляются один раз при импорте; `tg_range(t, t)` выдает `t` дважды.
- `w_rd.py` → `check_RD`:
  - результат `fntnl` сразу перезаписывается;
  - строка `S = S` ничего не делает.
- `w_rr.py`: деление на `Z*Z` без проверки.
- `w_calc.py`:
  - в `solve_G` внутренний `for i in range(len(root))` затирает счетчик внешнего цикла `i`;
  - `check_NS` — пустая заготовка;
  - `reset_consumptions` выходит на первом потребителе без узла обратки, не пересчитав остальных.
- `teplo/teplo1.py`: проверка `n != (-99999, 1)` бессмысленна — узлы атмосферы получают id
  −100000, −100001, …
- `sopr.py` → `ksi`: значения для 60 и 65 % одинаковые — проверить таблицу.
- `safe_spsolvefile.py` → `dump_system` падает при `t=None` или `b=None`.
- `config.py`:
  - `required=True` делает значения `default` бессмысленными;
  - дубли ключей `-ZULU`/`-zulu_utechki`, `-ZN0`/`-zulu_zn0`;
  - подмена `gettext.gettext` работает, только если `argparse` еще не был импортирован.
