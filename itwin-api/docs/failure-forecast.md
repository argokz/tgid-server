# Прогноз аварийности участков теплосети

Фаза 5 модернизации, шаг 1. `database/failure_forecast.py` (данные, признаки, проверка), `database/failure_model.py`
(модели на numpy), `routers/failure_forecast.py`, окно «Инструменты → Прогноз аварийности»
(`FailureForecastDialog.vue`).

## Модель

Вероятность повреждения участка за ближайшие H лет (по умолчанию 2). Градиентный бустинг деревьев на гистограммах
признаков (логистические потери, глубина 3, 150 деревьев, шаг 0,05; на каждом шаге — все повреждённые и до 20 000
неповреждённых участков с весом) — своя реализация на numpy: scikit-learn и бустинговых библиотек в среде API нет,
новых зависимостей на сервере не нужно. Для сравнения — логистическая регрессия (scipy) и одиночные признаки.

Признаки на дату среза T — только по прошлому: длина, условный диаметр, тип прокладки, вид сети, глубина
(`tgid_heat_depth`), возраст (перекладка до T, иначе первая прокладка), лет с капремонта до T; повреждения участка
(всего, за 3 года, лет с последнего), повреждения в 50 и 200 м (всего и за 3 года), частота повреждений фрагмента
на км. Метка — повреждение участка (журнал `defect`) в [T, T+H).

## Проверка — по времени

Модель учится на срезе T_train и проверяется на T_test = T_train + H — годах, которых не видела. Срезы — 1 января;
T_test — последний год, у которого окно [T, T+H) закрыто записями журнала и в нём не меньше 100 повреждений (в Астане
журнал после 2022 г. ведётся реже: 21–32 записи в год против 100–160 раньше). Итоговая модель учится на T_test и
даёт риск на сегодня (срез — день после последней записи журнала).

## Копии сети друг на друге

В базе Астаны магистрали лежат копиями по отопительным сезонам («Магистрали 2021-2022», «… 2022-2023 без прироста»,
…, «… 2026-2027 c приростом» — 11 фрагментов), журнал вешает повреждение на копию, текущую в тот сезон. Без склейки
история одной трубы размазана по копиям, копии без записей учат модель «не повреждается», а километры и план
считают трубу несколько раз. `canonical_lines`: участки сети (без внутренних схем узлов — они в условных координатах
и одинаковы у многих камер) из разных фрагментов с совпадающими концами (сетка 1 м) и длиной — одна труба; остаётся
участок самого нового фрагмента (наибольший id — в Астане 3179, основной по умолчанию), повреждения копий переносятся
на него. В Астане склеено 43,9 тыс. копий.

## Утечки, найденные и закрытые

Первый прогон дал ROC-AUC 0,97–0,98 — слишком хорошо. Проверка показала:

- **журнал ведётся по участкам с заполненным паспортом.** Материал изоляции заполнен у 95 % повреждённых участков и у
  21 % всех; один факт заполненности давал ROC-AUC 0,87 — модель училась «в журнале или нет», а не риску. Население —
  участки, у которых заполнено не меньше полей паспорта (диаметр, прокладка, материал и тип изоляции, вид сети, даты
  прокладки, перекладки, капремонта), чем у 90 % участков, повреждённых до среза обучения (Астана — 6 из 8, 28,2 тыс.
  из 290 тыс. участков после склейки копий, 92 % повреждённых);
- **материал и тип изоляции, состояние участка** обновляют при ремонте после повреждения — в признаки не берутся (и не
  нужны: на Астане 0,920 с ними и без них).

Цель плана — ROC-AUC от 0,75 на истории города — выполнена. Расчёт через API — 52 с. Вклад признаков итоговой модели:
возраст 38 %, повреждения в 200 м 18 % (за 3 года — 9 %), глубина 9 %, длина 6 %, диаметр 5 %. В начале списка —

## План перекладок — шаг 2

`database/relay_plan.py`, `routers/relay_plan.py`, вкладка «План перекладок» в окне прогноза (`RelayPlanPanel.vue`).

- **Польза** трассы — сумма по участкам: вероятность повреждения × последствия одного повреждения по критерию
  (`objective`): `consumers` — сколько потребителей отключит авария (шаг 3, по умолчанию), `load` — их нагрузка,
  Гкал/ч, `wear` — последствия оценки износа (`wear_out.consequence`, 1…2,4) × множитель расхода (`wear.flow_factor`),
  `failures` — только число повреждений. На Астане последствия в паспортах одинаковы (1,4 у всех) — `wear` почти
  совпадает с `failures`.
- **Копии одной трубы** в разных фрагментах склеиваются и в плане (`merge_copies`, тот же признак, что в прогнозе):
  без этого план перекладывал одну магистраль дважды.
- **Единица перекладки — трасса**: участки одного фрагмента между развилками; подача и обратка между одними узлами —
  один коридор; смена диаметра — граница. Выбор по отдельным участкам давал 2 769 обрезков по 2 м на 5 км.
- **Стоимость** — длина × расценка за метр по классу диаметра (`tgid_relay_price`, заполняет пользователь, миграция
  `20261101_relay_plan.sql`); расценок нет — бюджет в км. **Постоянные затраты объекта** (вскрытие, отключение,
  благоустройство) — в метрах трубы, по умолчанию 25 м: входят в порядок отбора, бюджет тратится на трубу. Вероятность
  повреждения почти не растёт с длиной, и без них «риск на метр» у коротких отводов огромный.
- **Отбор** — жадный по пользе на единицу стоимости; для сравнения — «самые старые первыми» в том же бюджете.

Астана до шага 3 (критерий `wear`, без склейки копий), бюджет в км:

| Затраты объекта | Бюджет | Объектов | Медиана объекта | Снимает ожидаемых повреждений | «Самые старые» |
|---|---|---|---|---|---|
| 0 м | 5 км | 1 717 | 1,8 м | 8,2 % | 0,1 % |
| 25 м | 5 км | 152 | 17 м | 4,4 % | 0,1 % |
| 25 м | 20 км | 593 | 16,5 м | 11,2 % | 0,9 % |
| 50 м | 20 км | 363 | 26 м | 9,6 % | 0,9 % |

План в деньгах на условных расценках (стенд, удалены после проверки) уводит вниз дорогие магистрали. Составление —
3–4 с.

## Последствия: кого отключит авария — шаг 3

`database/outage_consequence.py`: для каждого участка — потребители, нагрузка и социальные объекты (школы, детсады,
больницы, поликлиники, соцучреждения — по названию потребителя, `poi.classify`), которые отключит авария: зона
задвижек и потребители ниже закрытых задвижек без обходного питания — то же, что изоляция участка
(`simulate_outage_isolation`), но для всех участков за один обход:

- сеть сжимается в отсеки (узлы без задвижек, связанные участками без задвижек); камеры и участки с задвижками —
  отдельные вершины; нормально закрытые участки не проводят;
- авария в отсеке = удаление его вершины; без питания остаются поддеревья обхода в глубину от общего источника с
  low ≥ disc (точка сочленения) — нагрузки поддеревьев копятся в том же обходе;
- участок с задвижкой на нём самом (зона — отсеки обоих концов) — прямым обходом графа отсеков.

Сверка с изоляцией по участку: Астана — 60 участков из 60, Алматы — 40 из 40 (потребители зоны и ниже — точно,
нагрузка — до округления); тесты — 25 случайных сетей против той же изоляции. Расчёт всей сети — 13 с (Астана: 94,7
тыс. участков, 38,6 тыс. потребителей), таблица `tgid_line_consequence` (миграция `20261101_line_consequence.sql`);
считается при первом плане по отключениям, после изменения сети — кнопкой.

Астана, бюджет в км, затраты объекта 25 м, после склейки копий (24,3 тыс. участков; последствия известны у 22,1 тыс.):

|---|---|---|---|---|---|---|---|
| потребители | 5 км | 53 | 1,6 % | 17,1 % | 18,7 % | 5,6 % | 0,9 % / 4,2 % |
| нагрузка | 5 км | 55 | 1,4 % | 17,0 % | 19,2 % | 3,4 % | 0,9 % / 4,2 % |
| только повреждения | 5 км | 48 | 6,0 % | 2,7 % | 2,0 % | 2,7 % | 0,9 % / 4,2 % |
| потребители | 20 км | 109 | 5,0 % | 40,2 % | 43,1 % | 14,0 % | 1,3 % / 4,6 % |

сравнением, объекты, участки объектов.
