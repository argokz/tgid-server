# Персональные данные: маскирование по праву

Раздел 2б плана модернизации (152-ФЗ РФ, закон РК «О персональных данных и их защите»): ФИО физических лиц,
телефоны, e-mail, ИИН, лицевые счета и номера договоров потребителей видит полностью только пользователь с
правом **«Персональные данные потребителей полностью»** (`pii_view`). Остальным API отдаёт их замаскированными.
Данные в базе не меняются — их ведёт и десктоп.

Код: `database/pii.py` (правила и маскирование), `pii_middleware.py` (JSON-ответы API), право — `permissions.py`.
Тесты — `tests/test_pii.py`.

## Кто видит полностью

- Шаблоны ролей: **Редактор** и **Администратор**; Просмотр, Режимщик и Оператор — замаскированными.
- Пользователю можно дать или снять право отдельно («Пользователи → права», общие права).
- Пользователь-роль PostgreSQL (`AUTH_BACKEND=pg`) — с правом «акты» (`tgid_cap_acts`) или администратор.
- `PII_MASKING=false` выключает маскирование (закрытый стенд без ПДн).

## Что маскируется

Поле узнаётся по имени колонки, значение — по виду:

| Колонка | Пример | Зрителю |
|---|---|---|
| телефон (`phone`, `telefon`, `kontaktn…`) | `8-700-000-00-88` | `*-***-***-**-88` |
| владелец, абонент (`owner`, `abonent`, `vladelets…`) | `ИП ИВАНОВА МАРИЯ ПЕТРОВНА, тел. 8 700 000 0012` | `ИП И*** М. П., тел. * *** *** **12` |
| | `ТОО "Пример"` | без изменений — организация |
| договор, лицевой счёт, ИИН (`dogovor`, `contract_number`, `…schet`, `iin`) | `12345` | `*2345` |
| e-mail | `ivan@mail.kz` | `i***@mail.kz` |

ФИО узнаются в виде «Фамилия Имя Отчество» (в том числе казахские отчества: -ұлы, -қызы, и с буквами,
потерянными при перекодировке, — «Нурлан?ызы») и «Фамилия И. О.». ФИО сотрудников (начальники участков,
ответственные в журналах) — рабочие данные и не маскируются.

## Где действует

- Все JSON-ответы API (`pii_middleware.PiiMaskMiddleware`): ответ разбирается, только если в нём есть ключи
  полей ПДн; больше `PII_MAX_BYTES` (16 МБ — GeoJSON сети) — без разбора. Вход, администрирование пользователей
  и MCP — без маскирования.
- Выгрузки: отчёт сверки АЛСЕКО (`/api/alseko/reconciliation/report.xlsx`).
- На копии Алматы: нагрузки АЛСЕКО (`nagruzki.owner`, 21,5 тыс. записей, из них ~9,8 тыс. без формы юрлица —
  ИП и физлица, иногда с телефоном) — зритель видит ФИО предпринимателей и физлиц
  в виде «Фамилия → первая буква и звёздочки», договор — последние 4 цифры; редактор — полностью.

## Что ещё не закрыто

- **Слои GeoServer.** В Астане слой актов `act` (абонент — 8,6 тыс., телефон — 8,2 тыс. записей) и таблицы
  организаций публикует GeoServer, мимо API: атрибуты приходят в тайлах и в GetFeatureInfo без маскирования.
  Закрыть можно представлением с маскированием в базе и переключением слоя GeoServer на него (или исключением
  колонок из слоя) — это настройка сервера, её делает администратор при выкатке.
- Функции тайлов martin генерируются из слоёв GeoServer (`scripts/martin`) и наследуют их набор колонок.
- Прочие выгрузки Excel/Word — по мере появления в них полей ПДн.
