# FeatureServer для ArcGIS-клиентов

Фаза 2 плана модернизации, п. 12: слои сети ТГИД **только для чтения** по протоколу GeoServices REST (ArcGIS
Server), чтобы их подключали ArcGIS Pro, ArcGIS Online, QGIS, Esri Leaflet и GDAL. Код: `database/arcgis_features.py`,
`routers/arcgis.py`; веб — «Личный кабинет → ArcGIS и QGIS» (`components/ArcgisClientPanel.vue`). Тесты —
`tests/test_arcgis.py`, `tests/utils/arcgisClient.spec.ts`. Слои — те же, что у OGC API Features (`/api/ogc`).

## Слои

Адрес сервиса: `<адрес API>/api/arcgis/rest/services/TGID/FeatureServer`.

| № | Слой | Геометрия | Поля |
|---|---|---|---|
| 0 | Участки теплосети | полилиния | имя, узлы начала и конца, признак, Ду, внутренний диаметр, длина, состояние подачи и обратки |
| 1 | Узлы сети (основная схема) | точка | имя, вид узла |
| 2 | Потребители (точка узла присоединения) | точка | имя, вид (реальный / обобщённый), узел, нагрузка, Гкал/ч |
| 3 | Источники тепла | точка | имя, узел |
| 4 | Задвижки (середина участка) | точка | имя, участок, Ду, состояние |

У всех слоёв — `OBJECTID` (id объекта в базе) и `fileid` (фрагмент).

## Запрос `/query`

| Параметр | Что понимает |
|---|---|
| `where` | `1=1`, «поле = число» (числовое поле слоя или `fileid`, `OBJECTID`), `OBJECTID IN (…)`. Другое — ошибка: свой SQL не принимается |
| `objectIds` | номера через запятую |
| `geometry`, `inSR` | оболочка Esri JSON или `xmin,ymin,xmax,ymax`; 4326 или 3857/102100 |
| `outFields`, `returnGeometry` | `*` или список полей |
| `outSR` | 4326 или 3857/102100 |
| `resultOffset`, `resultRecordCount` | страницы до 2000; `exceededTransferLimit` — есть ещё (GDAL и QGIS листают сами) |
| `returnCountOnly`, `returnIdsOnly` | число объектов, список номеров |
| `f` | `json`, `pjson` (Esri JSON) или `geojson` (всегда WGS84) |

Ошибки — как у ArcGIS Server: HTTP 200 и `{"error": {"code", "message"}}`; 499 — нет ключа, 498 — ключ не принят.

## Вход

- Ключ выдаётся в веб-приложении: «Личный кабинет → ArcGIS и QGIS → Выдать ключ» (`POST /api/v1/arcgis/token`).
  Действует `ARCGIS_TOKEN_DAYS` дней (по умолчанию 90, не больше 365), **только на адресах FeatureServer**, с правами
  пользователя; смена пароля или блокировка закрывает его. Выдача пишется в журнал действий.
- ArcGIS Pro и ArcGIS Online: адрес сервиса с `?token=<ключ>` («Добавить данные → по адресу»).
- QGIS: соединение «ArcGIS REST Server», проверка подлинности «API Header»: `Authorization: Bearer <ключ>`.
- Обычный токен входа тоже принимается. Шлюз `AUTH_REQUIRED_GET` эти адреса пропускает — они проверяют ключ сами.
- Персональные данные маскируются как во всём API: ключ в адресе — без права `pii_view` (маскирование включено).

## Проверено

- GDAL (`ogrinfo`, `ogr2ogr`, драйвер ESRIJSON — тот же путь, что у QGIS) на копии Алматы: слой узлов прочитан целиком
  постранично (50 035 узлов), участки в оболочке Web Mercator выгружены в GeoPackage (241 участок, EPSG:3857, поля
  с типами).
- Копия Астаны: участков 324 209 — подсчёт 2–3 с, страница 2000 участков — 0,4 с, по области — 0,2 с; страница со
  смещением 200 000 — 3,7 с (клиенты обычно запрашивают по видимой области).
- ArcGIS Pro и ArcGIS Online вживую не проверялись (нет лицензии на стенде).
