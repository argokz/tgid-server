# Совместимость веба с десктопом gid8

Десктоп ТГИД (gid8) и веб (API + карта) работают **в одной базе города одновременно**: часть людей
правит сеть в десктопе, часть — в браузере. Любое изменение веба не должно мешать десктопу, и
наоборот: веб должен переживать то, что делает десктоп. Здесь — договорённость и как она проверяется.

## Как они делят базу

| | Десктоп gid8 | Веб |
|---|---|---|
| Подключение | ODBC, роль `tgid` или `postgres` (суперпользователь), приложение `Tgid-NN` | API — asyncpg; GeoServer — JDBC |
| Таблицы сети (`nodes`, `linesobj`, `heatpipesections`, карточки, справочники) | создаёт конвертер, читает и пишет | читает и пишет теми же правилами, что десктоп (пара П/О, тип узла = таблица расширения, длина в местной СК — см. память проекта и `database/topology*.py`) |
| Свои объекты | всё остальное в базе | таблицы, функции и индексы из `sql/` (список — ниже) |
| Переконвертация | `DROP DATABASE` + `CREATE DATABASE` + перенос данных | ничего не делает сама; через ≤ `DB_UPKEEP_INTERVAL_S` (600 с) API возвращает свои объекты |

## Правила для SQL веба

1. Таблицы десктопа — **только добавлять**: индекс, колонку `ADD COLUMN IF NOT EXISTS` без `NOT NULL`,
   функцию. Нельзя: удалить или переименовать таблицу или колонку, сменить тип, `SET NOT NULL`,
   добавить ограничение (`CHECK`, внешний ключ) — запись десктопа начнёт падать.
2. Триггер на таблице десктопа не должен отклонять запись десктопа. Пример — `tgid_territory`
   (`sql/pg_auth/04_rls.sql`): суперпользователь проходит без проверок через `tgid_auth.is_admin()`.
3. Правка данных десктопа в скриптах схемы — только разовая ручная починка (`sql/fixes/`), не в
   пунктах `city_schema`.
4. Всё, что API применяет сам (`database/city_schema.py`), должно запускаться повторно без ошибок:
   `IF NOT EXISTS`, `CREATE OR REPLACE`, `DROP TRIGGER IF EXISTS` перед `CREATE TRIGGER`.
5. Исключение из правил 1–3 — только записью в `ALLOWED` в `tests/test_desktop_compat.py` с причиной,
   почему десктоп это не заметит.

Правила проверяет `tests/test_desktop_compat.py` при каждом прогоне тестов. Сейчас в `ALLOWED`:
описание SRID 9998 в Астане и Шатуре (координаты в таблицах не меняются), колонка и триггер
`linesobj.internalnodeid` в Шатуре, RLS и триггер территории (не действуют на суперпользователя),
запись в журнал `audit_log`, ручная починка узлов без кода.

## Важное условие для RLS (права по территории)

RLS включается без `FORCE`, а триггер территории пропускает администратора. Десктоп сейчас ходит
суперпользователем (`tgid`, `postgres` — проверено по `pg_stat_activity` 28.10.2026), поэтому RLS его
не касается. **Если десктоп начнёт подключаться обычной ролью**, её нужно включить в `tgid_admin` или
дать ей политики — иначе десктоп перестанет видеть строки. Проверять перед включением RLS на проде.

## Что делает API при переконвертации

- Каждые 600 с (и при запуске) API сверяет oid базы в `pg_database`: при пересоздании он меняется.
  Тогда API пишет в журнал «База города … пересоздана», сразу сбрасывает кеши (граф отключений,
  каталог таблиц, колонки-ссылки на узлы) и сбрасывает их ещё раз, когда конвертер закончил.
- Возвращает свои объекты (пункты `city_schema`), пока база занята записью — ждёт.
- Состояние видно в `GET /health` → `city_schema` (`status`, `missing`, `recreated`, `recreated_at`) и
  в метриках `tgid_city_schema_ok`, `tgid_city_schema_missing`, `tgid_city_db_recreated`.

## Что теряется при переконвертации

Переконвертация пересоздаёт базу, поэтому **данные веба в ней пропадают**, хотя таблицы API вернёт:

| Таблица | Что это | Потеря |
|---|---|---|
| `card_template` | шаблоны карточек, которые завели пользователи | заметная — пользовательские данные |
| `object_authorship` | кто создал объект (права «только свои») | заметная — операторы перестанут править свои объекты |
| `topology_undo_log` | история правок веба, отмена/повтор | история до переконвертации |
| `calculation_protocol`, `wear_out`, `calculation_iznos`, `heatlosses_report_out` | протоколы и результаты расчётов | пересчитываются |

Как сохранять первые две (вынести в UsersDB или восстанавливать после переконвертации) — открытый
вопрос: зависит от того, сохраняет ли конвертер id объектов.

## Чек-лист нового SQL

- [ ] Файл в `sql/migrations/` (или `sql/<город>/`) и пункт в `database/city_schema.py`.
- [ ] Повторный запуск не падает.
- [ ] `pytest tests/test_desktop_compat.py tests/test_city_schema.py` зелёный.
- [ ] Если меняются таблицы десктопа — проверено, что десктоп gid8 открывает и сохраняет объект.
