# Наряды и заявки

Фаза 2 плана модернизации: заявка или дефект → наряд → бригада → выполнение → приёмка. Веб — «Журналы →
Наряды и заявки». Код: `database/work_orders.py`, `routers/work_orders.py`, таблицы веба
`tgid_work_order` и `tgid_work_order_event` (`sql/migrations/20261030_work_orders.sql`, API создаёт их сам,
`city_schema`). Тесты — `tests/test_work_orders.py`, `tests/utils/workOrders.spec.ts`.

## Статусы

| Статус | Что значит | Куда дальше |
|---|---|---|
| Заявка (`new`) | работа записана, исполнителя нет | назначить, отменить |
| Назначен (`assigned`) | есть бригада или ответственный | начать работу, вернуть в заявки, отменить |
| В работе (`in_progress`) | бригада на месте | выполнено, вернуть в назначенные, отменить |
| Выполнен (`done`) | бригада закончила, результат описан | принять и закрыть, вернуть в работу |
| Закрыт (`closed`) | работа принята — правки нет | — |
| Отменён (`cancelled`) | — | открыть снова |

Наряд с бригадой или ответственным создаётся сразу назначенным. Назначить без исполнителя и отметить
выполненным без описания «что сделано» нельзя (422). Каждый переход, правка и комментарий — строка истории
(кто, когда, из какого статуса в какой). Изменение по устаревшей версии наряда — 409 («обновите карточку»).
Просроченные — срок прошёл, а наряд ещё открыт (заявка, назначен, в работе).

## Связь с журналом дефектов (десктоп)

Наряд по дефекту берёт из дефекта участок, точку и описание. При «В работе» дефекту ставится дата начала
ремонта (если пустая) и состояние «Ремонт», при «Выполнен» — дата завершения и «После ремонта» (справочник
`statedefect`). Уже заполненные даты не переписываются; остальные поля дефекта наряд не трогает. Десктоп
видит эти изменения в своём журнале; таблицы нарядов он не читает.

## Бригады

Справочник «Бригады» (`brigades`, общий с десктопом) правится в «Исходные данные → Справочники». У десктопа
мастер, подразделение и численность обязательны — справочник их и требует (раньше база отвечала ошибкой 500).

## Адреса API

| Запрос | Что | Право |
|---|---|---|
| `GET /api/v1/work-orders/lookups` | бригады, ответственные, виды, срочность, статусы и переходы | вход |
| `GET /api/v1/work-orders` | список (`status`, `brigade_id`, `fileid`, `q`, `open_only`), счётчики, просрочка | вход |
| `GET /api/v1/work-orders/geojson` | открытые наряды точками (слой карты) | вход |
| `GET /api/v1/work-orders/{id}` | наряд с историей | вход |
| `POST /api/v1/work-orders` | создать | «Журналы» |
| `PATCH /api/v1/work-orders/{id}` | изменить (`revision`) | «Журналы» |
| `POST /api/v1/work-orders/{id}/transition` | сменить статус (`to`, `revision`, `result`, `note`) | «Журналы» |
| `POST /api/v1/work-orders/{id}/comments` | комментарий | «Журналы» |

Запись — ещё и при включённых правках (`MUTATIONS_ENABLED`), действия пишутся в журнал действий (`JOURNAL`).
Пользователю-роли PostgreSQL таблицы нарядов выдаются вместе с журналами (`sql/pg_auth/03_grants.sql`).
