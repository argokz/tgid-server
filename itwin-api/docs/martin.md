# martin: векторные тайлы сети прямо из PostGIS

С 29.10.2026 (фаза 1 модернизации) слои сети — участки, узлы и здания — могут отдаваться
[martin](https://github.com/maplibre/martin) (MapLibre, Apache-2.0/MIT) вместо GeoServer. Стили, подписи,
карточки объектов и остальные слои по-прежнему берутся из GeoServer.

## Зачем

- **Скорость.** Тайл участков на прогретой базе строится за 20–30 мс. GeoServer на том же SQL отвечает
  за 100–250 мс, а его кеш GWC надо сбрасывать после каждой правки сети.
- **Без ручной настройки GeoServer на город.** Функции тайлов генерируются из SQL-представлений
  рабочей области города, а после переконвертации базы API возвращает их сам.
- **Один процесс на все города.** martin держит своё подключение к базе каждого города.

## Как устроено

1. `scripts/martin/build_martin_functions.py` читает `featuretype.xml` слоёв рабочей области GeoServer
   (`heatpipesections`, `uzel`, `zdaniya_2`, `zdaniya_tu`) и создаёт в базе города функции
   `tgid_mvt_<слой>(z, x, y, query_params json) → bytea`:
   - SQL, параметры и регулярные выражения проверки — как в SQL-представлении GeoServer;
   - веб передаёт ту же строку `viewparams=fragments:74;RAS:on;rev:N;`, функция разбирает её так же,
     как GeoServer;
   - атрибуты и имя слоя внутри тайла — как у GeoServer, поэтому стили MapLibre работают без изменений;
   - полоса вокруг тайла: у точек 512 из 4096 (значки у края не обрезаются), у линий и полигонов 64;
   - ниже минимального зума стиля слоя — пустой тайл (здания видны с z14, участки и узлы — с z9);
   - колонки `numeric` приводятся к `float8`.
2. `scripts/martin/build_martin_config.py` пишет `config.yaml` martin: источник `<город>_<слой>`
   (`almaty_heatpipesections`) у каждого города, у которого в базе есть функции.
3. Веб (`server/api/geoserver-layers.ts`) при заданном `MARTIN_TILES_URL` берёт тайлы слоёв из
   `MARTIN_LAYERS` рабочей области `MARTIN_WORKSPACE` из martin:
   `<MARTIN_TILES_URL>/<MARTIN_SOURCE_PREFIX><слой>/{z}/{x}/{y}?viewparams=…`. Без `MARTIN_TILES_URL`
   всё остаётся как раньше.
4. nginx публикует martin под `/geoserver/tiles/`. Там действует cookie сессии GeoServer `tgid_gs` и
   та же проверка входа (`/auth/check`). Город проверяется по префиксу источника
   (`cities.geoserver_request_cities`). Ключ кеша проверки включает источник: «можно» для Алматы не
   откроет Астану.
5. После переконвертации базы города API возвращает функции сам: пункт `city_schema`
   «функции тайлов martin» из файла `MARTIN_SQL_FILE`. Пока функций нет, martin с `--on-invalid warn`
   продолжает работать для остальных городов.

## Установка (на сервере, от администратора)

1. Обновить код API и веба до ветки с martin, собрать веб.
2. Запустить `H:\deploy\install-tgid-martin.cmd` — он вызывает `scripts/martin/install-martin.ps1`
   с архивом `H:\deploy\martin\martin-1.16.1-x86_64-pc-windows-msvc.zip` и пишет журнал в
   `H:\deploy\logs\install-tgid-martin.log`.

Что делает скрипт (повторный запуск безопасен):
- кладёт `martin.exe` в `C:\tgid\martin`;
- создаёт функции в базах городов;
- пишет `config.yaml`; в нём пароль базы, поэтому доступ только у администраторов и SYSTEM;
- ставит службу `tgid-martin` на `127.0.0.1:3005`;
- подключает `C:\nginx\conf\tgid-martin.conf` и строку источника в карту `$tgid_gs_scope`
  (бэкапы `*.bak-martin-*`, `nginx -t`; при ошибке файлы возвращаются из бэкапа);
- задаёт `MARTIN_*` службам веба и перезапускает их;
- задаёт `MARTIN_SQL_FILE` службам API (вступит в силу при следующем их перезапуске).

Только часть городов: `-Only almaty,astana`. Если в рабочей области нет какого-то слоя (в Астане нет
`zdaniya_2`), он пропускается.

## Откат

`install-martin.ps1 -Disable` убирает `MARTIN_*` у служб веба и перезапускает их: тайлы сети снова идут из
GeoServer. Служба martin и nginx остаются, но не используются.

## Когда перегенерировать

Если изменили SQL-представление слоя в GeoServer (новая подпись, новый параметр), перезапустите
`install-tgid-martin.cmd`: функции, конфиг и файлы `MARTIN_SQL_FILE` обновятся.

## Проверка

- `http://127.0.0.1:3005/catalog` на сервере — список источников `<город>_<слой>`;
- в инструментах разработчика браузера тайлы сети — `…/geoserver/tiles/almaty_heatpipesections/…`, ответ
  200 (или 204 ниже минимального зума слоя);
- журнал службы: `H:\deploy\logs\tgid-martin.err.log`.
