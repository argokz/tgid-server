# Формы обходов

Фаза 2 плана модернизации, п. 8 раздела 2а (конструктор форм в духе Survey123 / ODK, подмножество XLSForm).
Что бригада отмечает на осмотре — состояние люка, вода в камере, температура, признаки утечки, фото — задаётся
формой, а не свободным комментарием: ответы одинаковые у всех бригад, их можно выгрузить и посчитать.

- **Администратор** собирает форму в «Эксплуатация → Формы обходов» или загружает готовую XLSForm (Excel-формат
  ODK, KoboToolbox, Survey123) и сразу видит, как форму увидит бригада.
- **Диспетчер** прикрепляет форму к наряду («Форма обхода» при создании наряда или в его карточке).
- **Бригада** заполняет её в полевом приложении (`/field`) — и без связи: форма хранится на телефоне, заполнение
  уходит через ту же очередь, что «Начать» и фото. Форма «на каждом узле обхода» заполняется у каждого узла
  маршрута (кнопка у узла), «раз на наряд» — кнопкой в карточке наряда.
- **Ответы** — в карточке наряда («Заполненные формы», с фото) и в Excel по форме (строка — заполнение).

Код:
- API: `database/forms.py`, `routers/forms.py`, миграция `sql/migrations/20261031_forms.sql` (API применяет её
  сам — `city_schema`; добавляет `tgid_work_order.form_id`), тесты `tests/test_forms.py`;
- веб: конструктор `components/FormsDialog.vue`, заполнение и просмотр `components/forms/FormRenderer.vue`, окно
  бригады `components/FieldFormDialog.vue`, правила `utils/forms.ts` (те же, что на сервере), тесты
  `tests/utils/forms.spec.ts`; выбор формы и ответы — `components/WorkOrdersDialog.vue`; очередь — `pages/field.vue`,
  `utils/fieldQueue.ts` (действие `form`).

## Поля

| Тип | XLSForm | Ответ |
|---|---|---|
| Текст | `text` | строка до 2000 символов |
| Целое число, Число | `integer`, `decimal` | число; границы «не меньше / не больше» (`constraint` `. >= N and . <= M`) |
| Выбор одного, Выбор нескольких | `select_one список`, `select_multiple список` | значение варианта / список значений |
| Дата | `date` | ГГГГ-ММ-ДД |
| Да / отметка | `acknowledge` | да или пусто (обязательная — нужно отметить) |
| Пояснение | `note` | без ответа: текст для бригады |
| Фото | `image` | до 5 фото; это фото наряда (видны и в «Фото с места работ») |

У поля — подпись, имя (латиница: колонка выгрузки и ключ в API), подсказка, «обязательное» и **условие показа**:
«показывать, если поле выше = / ≠ значение» (у выбора нескольких — «выбрано»; у отметки — «да»). Пока на
поле-условие не ответили, зависимое поле скрыто. Скрытые поля не сохраняются и не проверяются.

**Версии.** Правка полей сохраняет новую версию формы; прежние заполнения показываются и выгружаются по своей
версии. Изменить только название или описание — версия та же. Выключенная форма не предлагается для новых нарядов,
но её заполнения и выгрузка остаются.

## Импорт XLSForm

Листы `survey`, `choices` и необязательный `settings` (`form_title` — название формы). Подпись — колонка
`label::Русский (ru)`, если есть, иначе первая `label`. Что переносится — типы из таблицы выше, `required`,
`hint`, `relevant` вида `${поле} = 'значение'`, `${поле} != 'значение'`, `selected(${поле}, 'значение')`,
`constraint` вида `. >= N and . <= M`. Служебные поля (`start`, `end`, `deviceid`, `calculate` …) пропускаются —
время, автора и координаты ТГИД пишет сам. Группы раскрываются в общий список. Что не перенесено (`geopoint`,
повторы, сложные условия), перечисляется в окне до сохранения — форма открывается в конструкторе, её можно
поправить.

## Адреса API

| Адрес | Кто | Что |
|---|---|---|
| `GET /api/v1/forms?active=` | вошедший | формы с полями текущей версии и числом заполнений |
| `GET /api/v1/forms/types` | вошедший | типы полей |
| `GET /api/v1/forms/{id}?version=` | вошедший | форма (версия) |
| `POST /api/v1/forms` | администратор | `{name, description, scope: order \| point, schema: {fields}}` |
| `PUT /api/v1/forms/{id}` | администратор | изменить; поля изменились — новая версия |
| `PATCH /api/v1/forms/{id}` | администратор | `{active}` |
| `POST /api/v1/forms/import-xlsform` | администратор | файл .xlsx до 2 МБ → `{form, warnings}` (без записи) |
| `GET /api/v1/forms/{id}/export.xlsx` | право «Выгрузка» | заполнения в Excel: наряд, узел, кто, когда, где, ответы (время — местное) |
| `POST /api/v1/forms/submissions` | право «Журналы» | `{form_id, version, work_order_id, node_id, answers, client_id, lon, lat, filled_at}` → 201; повтор с тем же `client_id` — 200 и прежнее заполнение; ошибки — 422 с перечнем полей |
| `GET /api/v1/work-orders/{id}/forms` | вошедший | заполнения наряда: ответы, поля своей версии, фото (`client_id` → id фото наряда; ещё не дошедшее — null) |

Наряд: `form_id` в `POST /api/v1/work-orders` и `PATCH` (0 — снять форму); в ответе — `form_name`, `form_version`,
`form_scope`. Форма «на каждом узле» требует `node_id`: в наряде без маршрута обхода бригада заполняет её по узлу
наряда.

## Проверено (копия Алматы, 31.10.2026)

- Тестовая XLSForm (вымышленный осмотр камеры, 9 строк, лист `choices`, `settings`): 7 полей с условиями и
  границами; `geopoint` — в предупреждениях, `start` пропущен.
- API: форма → наряд с формой → заполнение (201), повтор тем же ключом (200, без дубля), ответы с ошибками (422:
  «Что с люком: обязательное поле; Уровень воды: не больше 300; Температура: нужно целое число»), Excel.
- Правка полей → версия 2; повтор без изменений — та же версия; прежние ответы — по версии 1; в Excel — новая
  колонка.
- Браузер: конструктор с предпросмотром (условие открывает «Что с люком»); полевое приложение на ширине телефона —
  пустая форма не сохраняется («Исправьте поля: 1»), заполненная дошла до сервера; API остановлен — форма в очереди
  («Заполнена: 2 · ждёт отправки: 1»), API запущен — ушла сама за 30 с; ответы в карточке наряда у диспетчера.
  Тестовые данные удалены.
- Не проверено в браузере: фото в форме (выбор файла камеры в панели браузера недоступен) — фото уходит обычным
  фото наряда, связь по ключу проверена через API.
