# Паспорт участка тепловой сети (Excel, формы 1–15)

Состояние на 2026-09-26.

## Откуда код
`passport_module/` — паспорт из десктопа (gid8, `python/docs/passport`), написанный под MS SQL.
Эндпоинты: `POST /api/db/object/{table}/{id}` (table = `uchastok_ms` | `uchastok_rs` | `linesobj` |
`nodes`), дерево участков `GET /api/passports/hierarchy`, диагностика `GET /api/passports/diagnostics`.
Порядок участков ПТС строится на лету (`sort_graph.make_graph`) по привязке труб к участку.
Таблицы `sortLinesForUchastok` / `sortNodesForUchastok` (gid6 `OnCreateSortNode`) паспорту не нужны.

## Данные: где паспорт вообще возможен
Паспорт строится по трубам участка — `heatpipesections.magistralSite` (МС) / `distSite` (РС).

В вебе — инструмент «Участки ПТС» (ниже); списком — `scripts/etl_site_pipe_from_csv.py`.

## Инструмент «Участки ПТС» (этап 9)
API `/api/v1/pts/*` (`routers/pts.py`, `database/pts_sites.py`), web `PtsSitesDialog.vue`:
- дерево участков МС/РС (начальник → участок) с числом и длиной привязанных труб;
- карточка участка: создание, правка (поля `tab/ps/uchastok_*.txt`, типы из схемы БД,
  справочники из `gid.lookup`; версия `xmin` → 409), удаление (есть трубы → 409, либо
  `unassign_pipes=true` — привязка снимается в той же транзакции);
- назначение/снятие привязки: трубы выбором на карте или цепочкой узлов (кратчайший путь по
  линейным объектам между соседними узлами; к участку идут только трубы пути).
  Пишется как в десктопе: МС → `magistralsite`, `distsite` = NULL; РС — наоборот.
  Реализовано групповыми установщиками `pts_site_ms` / `pts_site_rs` / `pts_site_clear`:
  dry-run → apply с `expected_changes`, audit_log группой, отмена `/api/v1/group-setters/undo`.
- Живая проверка (almatygid_copy, 2026-09-28): тестовый РС, цепочка из 2 узлов → 15 труб Ду 500
  (1,13 км); паспорт `POST /api/db/object/uchastok_rs/{id}` — все 15 форм с данными
  (Ф1: узлы, диаметры, длины подачи/обратки). Тестовый участок и привязки удалены.

## Что было сломано и исправлено (коммит d11ed4d)
На PostgreSQL работали только титульный лист, Ф1 и Ф8. Остальные формы падали на диалекте
MS SQL, а `excel.write_table` делал `exit(3)` — запрос паспорта умирал целиком.

- `STPointN/STDistance` → PostGIS (`sql.first_point`, `ST_DWithin` по колонке — работает индекс).
- Привязка объектов к трубам: в десктопе два независимых `ROW_NUMBER` (труба и узел) с условием
  `rn=1 and rn2=1` — объекты молча выпадали (МС 19: попадало 7–10 из 98 задвижек, какие —
  зависело от плана запроса). Теперь одна нумерация: ближайшая труба, затем ближайший узел.
- Ф9, Ф13–Ф15: функции `getPts_*` (в PG их нет) переведены в `journals_pg.py`; Ф10 — на месте.
- Ф11 `FOR XML PATH` → `string_agg`; `VALUES` с `NULL::int`; алиасы Ф15 длиннее 63 байт.
- `make_graph`: участок ПТС с ветвлением (3 конца) обрывал весь паспорт — теперь берутся
  первый и последний концы; убран вызов `graph2.unite` (O(N²), ничего не менял): РС 227 — 127 → 14 с.
- Мойибейк в заголовках форм (`Р¤РРћ` → «ФИО»), жёстко прописанные учётные данные MS SQL.
