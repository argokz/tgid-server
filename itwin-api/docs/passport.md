# Паспорт участка тепловой сети (Excel, формы 1–15)

Состояние на 2026-09-26.

## Откуда код
`passport_module/` — паспорт из десктопа (gid8, `python/docs/passport`), написанный под MS SQL.
Эндпоинты: `POST /api/db/object/{table}/{id}` (table = `uchastok_ms` | `uchastok_rs` | `linesobj` |
`nodes`), дерево участков `GET /api/passports/hierarchy`, диагностика `GET /api/passports/diagnostics`.
Порядок участков ПТС строится на лету (`sort_graph.make_graph`) по привязке труб к участку.
Таблицы `sortLinesForUchastok` / `sortNodesForUchastok` (gid6 `OnCreateSortNode`) паспорту не нужны.

## Данные: где паспорт вообще возможен
Паспорт строится по трубам участка — `heatpipesections.magistralSite` (МС) / `distSite` (РС).

| база | трубы с привязкой к участку | вывод |
|---|---|---|
| almatygid (прод), все снимки Алматы | 0 из 98 019 | паспорт пустой по данным: участки заведены (60 МС, 34 РС), но трубы к ним не привязаны |
| astanagid_2026_03_17 | 77 230 из 191 068 | паспорт строится |

Паспорта — функция Астаны. Для Алматы нужна привязка труб к участкам (в десктопе — поле
«Участок МС/РС» в свойствах трубы и назначение выделенным трубам `GidWidget::onSaveMS/onSaveRS`).
В вебе — инструмент «Участки ПТС» (ниже); списком — `scripts/etl_site_pipe_from_csv.py`.

## Инструмент «Участки ПТС» (этап 9)
API `/api/v1/pts/*` (`routers/pts.py`, `database/pts_sites.py`), web `PtsSitesDialog.vue`:
- дерево участков МС/РС (начальник → участок) с числом и длиной привязанных труб;
- карточка участка: создание, правка (поля `tab/ps/uchastok_*.txt`, типы из схемы БД,
  справочники из `gid.lookup`; версия `xmin` → 409), удаление (есть трубы → 409, либо
  `unassign_pipes=true` — привязка снимается в той же транзакции);
- назначение/снятие привязки: трубы выбором на карте или цепочкой узлов (кратчайший путь по
  линейным объектам между соседними узлами; к участку идут только трубы пути).
  Пишется как в десктопе: МС → `magistralsite`, `distsite` = NULL; РС — наоборот.
  Реализовано групповыми установщиками `pts_site_ms` / `pts_site_rs` / `pts_site_clear`:
  dry-run → apply с `expected_changes`, audit_log группой, отмена `/api/v1/group-setters/undo`.
- Живая проверка (almatygid_copy, 2026-09-28): тестовый РС, цепочка из 2 узлов → 15 труб Ду 500
  (1,13 км); паспорт `POST /api/db/object/uchastok_rs/{id}` — все 15 форм с данными
  (Ф1: узлы, диаметры, длины подачи/обратки). Тестовый участок и привязки удалены.

## Что было сломано и исправлено (коммит d11ed4d)
На PostgreSQL работали только титульный лист, Ф1 и Ф8. Остальные формы падали на диалекте
MS SQL, а `excel.write_table` делал `exit(3)` — запрос паспорта умирал целиком.

- `STPointN/STDistance` → PostGIS (`sql.first_point`, `ST_DWithin` по колонке — работает индекс).
- Привязка объектов к трубам: в десктопе два независимых `ROW_NUMBER` (труба и узел) с условием
  `rn=1 and rn2=1` — объекты молча выпадали (МС 19: попадало 7–10 из 98 задвижек, какие —
  зависело от плана запроса). Теперь одна нумерация: ближайшая труба, затем ближайший узел.
- Ф9, Ф13–Ф15: функции `getPts_*` (в PG их нет) переведены в `journals_pg.py`; Ф10 — на месте.
- Ф11 `FOR XML PATH` → `string_agg`; `VALUES` с `NULL::int`; алиасы Ф15 длиннее 63 байт.
- `make_graph`: участок ПТС с ветвлением (3 конца) обрывал весь паспорт — теперь берутся
  первый и последний концы; убран вызов `graph2.unite` (O(N²), ничего не менял): РС 227 — 127 → 14 с.
- Мойибейк в заголовках форм (`Р¤РРћ` → «ФИО»), жёстко прописанные учётные данные MS SQL.

## Сверка с десктопом и паспорта по начальникам (2026-10-10)
Эталон — текущий десктопный скрипт `gid8/python/docs/passport_ps/p.py` (последняя правка автора —
коммит 921fc9e, 19.12.2024), запущенный на той же базе `astanagid_2026_09_22` с теми же фрагментами
(база — только чтение, `PGOPTIONS=-c default_transaction_read_only=on`); книги сравнивались
поячеечно (значения, объединения, ширины, оформление).

Расхождения веба и что сделано:
- **Фрагменты.** Десктоп строит паспорт по подключённым фрагментам (`GidWidget::Passport` →
  `-fragments m_par`), веб — по всей базе. В Астане трубы участков скопированы в 11
  фрагментов-вариантов магистралей: РС 227 без фильтра — 788 строк Ф1 и 20,7 км по подаче вместо
  338 строк и 7,5 км. Теперь веб передаёт фрагменты карты (`fragments` у задачи `passport`,
  `?fragments=1,2` у синхронного эндпоинта).
- **Строки Ф1, Ф8 и форм объектов.** В 921fc9e автор десктопа перевёл паспорт на строку на трубу
  (узлы самой трубы, `mark_line.ord`, без join `mark_pts`; объекты — по id трубы). В веб попала
  более старая копия, склеивавшая трубы от узла ПТС до узла ПТС (у ветвящегося участка ответвления
  пропадали). `sql.py` приведён к 921fc9e.
- **Привязка объектов по всей геометрии.** 921fc9e: `ST_Distance(z.shape, l.shape)` вместо первой
  точки — веб по умолчанию тоже (`use_first_point=False`); линейный канал у трубы больше не теряется.
- **Скорость.** Формы строятся параллельно, как в десктопе (`PASSPORT_FORM_WORKERS`, по умолчанию 3 —
  `max_connections` сервера общий для всех баз): РС 2992 — 16,9 → 3,9 с.

Итог сверки (фрагменты по умолчанию веба Астаны):

| участок | результат |
|---|---|
| РС 2992, МС 119 | все 10 листов десктопа совпадают поячеечно, включая оформление |
| МС 43, РС 227 | тот же состав строк и суммы по всем числовым столбцам; отличаются порядок строк и, для объектов ровно в узле на стыке двух труб, к какой из труб объект отнесён. Десктоп сам недетерминирован: два его запуска на РС 227 дают разный порядок; веб — по id трубы, всегда одинаково |
| МС 19 | десктоп паспорт не строит («Страшная ошибка» на ветвлении участка ПТС, файла нет), веб строит |

Отличия веба, оставленные сознательно: листы Ф9–Ф15 (в десктопе выключены — функций `getPts_*`
в PostgreSQL нет; в вебе переведены, `journals_pg.py`), одна нумерация «труба, затем узел»
при привязке объектов (в десктопе объект мог выпасть).

**Паспорта по начальнику участка.** В доке ПТС десктопа участки сгруппированы по начальникам, но
паспорт строится по одному участку. В вебе (диалог «Отчёты и паспорта», кнопка архива у начальника
в ветке МС или РС) — фоновая задача `passport_chief` {`nach_id`, `kinds`, `fragments`}: ZIP с
паспортом каждого участка в формате выше и «Перечень участков.xlsx» (вошёл / пропущен: нет труб
в выбранных фрагментах / не сформирован и почему). Ход работы — в статусе задачи («Участок 3 из
40: РС 227»). Бейсенбаев К.Е., 40 РС — 3,3 мин, 1,8 МБ; 6 МС Афризонова — 23 с.
