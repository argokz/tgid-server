# Плановые и аварийные отключения

Фаза 2 плана модернизации: участок, узел или наряд → расчёт изоляции → задвижки и потребители → объявление и
список для уведомления → отключили → включили. Веб — «Журналы → Отключения» (и кнопка «Отключение для работ»
в карточке наряда). Код: `database/outages.py`, `routers/outages.py`, таблицы веба `tgid_outage` и
`tgid_outage_event` (`sql/migrations/20261030_outages.sql`, API создаёт их сам). Тесты — `tests/test_outages.py`,
`tests/utils/outages.spec.ts`.

## Что сохраняется

При планировании выполняется расчёт изоляции (тот же, что «Локализация аварий»,
`database/outage_simulation.py`) и снимок сохраняется в отключении:

- задвижки, которые нужно закрыть (обязательные — первыми);
- потребители зоны и потерявшие питание ниже по сети (с отметкой), их нагрузка;
- зона на карте — буфер 40 м вокруг отключаемых участков, полигоном.

Сеть могли поправить после планирования — «Пересчитать» (пока отключение не началось). Пересчёт пишется в
историю с тем, как изменились числа.

## Статусы

Запланировано → Объявлено → Идёт (фактическое начало) → Завершено (фактическое окончание); запланированное и
объявленное можно отменить или вернуть в план; отменённое — запланировать снова. Изменение по устаревшей версии
— 409.

## Пересечения

В карточке — другие открытые отключения, у которых время перекрывается и есть общие потребители: «общих
потребителей N». Служба видит, что дом отключат дважды или на дольше, чем объявлено.

## Уведомления

- «Список для уведомления» — Excel: сроки, причина, текст объявления, все потребители (нагрузка, ниже по сети,
  координаты) и лист задвижек.
- «Текст объявления» — готовая фраза для SMS, сайта, письма (до 20 потребителей по названию и «и ещё N»).

Рассылкой ТГИД не занимается: текст и список передаются в службу, которая рассылает.

## Публичная карта отключений

`GET /api/v1/public/outages` — без входа, GeoJSON зон объявленных и идущих отключений, у которых в карточке включено
«Показывать на публичной карте»: номер, вид, сроки, число потребителей и текст для жителей. Названия потребителей,
нагрузка и внутренняя причина в ленту не попадают. По умолчанию лента выключена (404): включает служба
переменной `PUBLIC_OUTAGES_ENABLED=true` у API. Страница для жителей — следующий шаг фазы 2.

## Адреса API

| Запрос | Что | Право |
|---|---|---|
| `GET /api/v1/outages` | список (`status`, `open_only`, `q`) и счётчики | вход |
| `GET /api/v1/outages/geojson` | зоны открытых отключений | вход |
| `GET /api/v1/outages/{id}` | отключение: задвижки, потребители, зона, история, пересечения | вход |
| `POST /api/v1/outages` | запланировать (`line_id`, `node_id` или `work_order_id`; сроки, причина) | «Журналы» |
| `PATCH /api/v1/outages/{id}` | сроки, причина, публикация (`revision`) | «Журналы» |
| `POST /api/v1/outages/{id}/recompute` | пересчитать изоляцию | «Журналы» |
| `POST /api/v1/outages/{id}/transition` | сменить статус | «Журналы» |
| `GET /api/v1/outages/{id}/announcement` | текст объявления | вход |
| `GET /api/v1/outages/{id}/notification.xlsx` | список для уведомления | «Выгрузки» |
| `GET /api/v1/public/outages` | публичная лента | без входа, если включена |

Запись — ещё и при `MUTATIONS_ENABLED`; действия — в журнале действий (`JOURNAL`); гранты роли PG — вместе с
журналами (`sql/pg_auth/03_grants.sql`).
