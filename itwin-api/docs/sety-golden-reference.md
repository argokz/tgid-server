# Эталонные расчёты sety

Набор эталонных расчётов, чтобы любую новую поставку sety и любую правку проверять одной
командой. Скрипты: `scripts/golden/run_reference.py` (прогон и снимки), `scripts/golden/compare_calc.py`
(сверка), `scripts/golden/sety_probe.py` (зонды для проверки ревью без правки sety).

## Как это устроено

- Каждый **случай** — фрагмент × режим × Tн на **копии** базы. Расчёт запускается так же, как
  воркер (`worker._sety_base_cmd` + `sety_modes.build_sety_args`): пароль только из окружения,
  не аргументом. Базы не с суффиксом `_copy` отклоняются всегда.
- Перед каждым случаем — **прогрев** тем же расчётом: sety берёт источник у узлов с заданным
  напором из последнего расчёта фрагмента (`read_zn.read_zn0`), прогрев делает это состояние
  одинаковым. `PYTHONHASHSEED=0` — порядок шаблонов внутренних схем фиксирован.
- **Магистраль.** Узлы с заданным напором берут напоры, температуры и источник из последнего
  расчёта фрагмента-магистрали (`setPressNodes.fragment_resultID`; у Алматы 72 это 74). Перед
  случаем магистраль пересчитывается тем же режимом и Tн, граничные условия пишутся в
  `meta.json` (`boundary`). Если за время попытки кто-то ещё посчитал этот фрагмент или его
  магистраль (в `almatygid_copy` идут сверки heatnet), случай повторяется (`--retries`, по
  умолчанию 3). Если граничные условия всё же разошлись, отчёт об этом пишет.
- **Синтетические узлы** (id < 0, внутренние узлы эквивалентных схем в фактическом режиме)
  нумеруются заново при каждом расчёте, поэтому сверяется только их количество.
- **Снимок** случая: `meta.json` (параметры, отпечаток кода sety, `calc_params`, баланс и
  сообщения протокола, вход `read_zn0`, чужие расчёты за время прогона), `<таблица>.csv`
  по всем `*_out` (все колонки, кроме `id`/`calculationid`), `objects.csv` (имена узлов и
  участков для отчёта), `protocol.txt` и `stderr.txt` (ход итераций решателя).
- Снимки лежат **вне репозитория** (репозиторий публичный, а это расчёт реальной сети):
  `$SETY_GOLDEN_DIR`, по умолчанию `H:\projects\tgid-app\golden\sety`. Проверки — в
  `_checks/<время>/`, зонды — в `_probes/<зонд>_<время>/`.

| случай | база | фрагмент | Tн | режим |
|---|---|---|---|---|
| almaty74_plan | almatygid_copy | 74 | −20 | плановый |
| almaty72_plan | almatygid_copy | 72 | −20 | плановый |
| almaty74_fact | almatygid_copy | 74 | −20 | фактический, эквивалентные сопротивления (`-a`) |
| shatura3252_plan | shatura_copy | 3252 | −25 | плановый |
| astana_plan_tg | astanagid_copy | 3179 | −31,2 | плановый по температурному графику (`-tg`) |

Tн −20 у Алматы: при −25…−30 sety останавливается проверкой «должна быть от −25 до 8» у части
температурных графиков.

## Команды

Из `itwin-api/itwin-api`, с `PYTHONIOENCODING=utf-8` (иначе кириллица в консоли Windows):

```bash
venv/Scripts/python.exe scripts/golden/run_reference.py list
venv/Scripts/python.exe scripts/golden/run_reference.py capture            # снять эталоны (все случаи)
venv/Scripts/python.exe scripts/golden/run_reference.py check              # пересчитать и сверить
venv/Scripts/python.exe scripts/golden/run_reference.py check --sety-root <каталог, где лежит sety/>
venv/Scripts/python.exe scripts/golden/run_reference.py check --cases almaty74_plan --tol-temp 0.1
```

- `check` печатает сводку (`summary.md`) и кладёт `<случай>.md` рядом со снимками кандидата.
  Код возврата 0 — всё совпало.
- Новая поставка sety: распаковать её во временный каталог (`<tmp>/sety/...`) и
  `check --sety-root <tmp>` — до трёхстороннего слияния, чтобы видеть, что меняет сама поставка;
  после слияния — `check` без `--sety-root`.
- Допуски по классам величин (значение в допуске, если укладывается в абсолютный **или**
  относительный): напор 0,01 м, расход 0,01 т/ч, температура 0,05 °C, нагрузка 1e-4 Гкал/ч,
  прочее 0,001; относительный 0,1 %. Меняются `--tol-head/--tol-flow/--tol-temp/--tol-load/--tol-rel`.
- Отчёт: «Что ушло и где» (таблица, величина, сколько вне допуска, худшее место с именем узла
  или участка), худшие значения, раздел «Нагрузки b101–b106» (суммы по видам, поучастково и
  тождество b101 = b102+…+b106 у каждой стороны), баланс из протокола, сообщения протокола
  (что пропало и что появилось). `--ignore-protocol` — сообщения не влияют на итог.
- Сверка двух готовых снимков без БД: `compare_calc.py --ref-dir <случай> --new-dir <случай>`;
  двух каталогов проверок: `run_reference.py compare --new-dir <каталог>`.
- В `meta.json` кандидата `foreign_calcs` — чужие расчёты в той же копии за время прогона
  (например, сверки heatnet в `almatygid_copy`). sety зависит от них только через `read_zn0`;
  если при этом есть расхождения, отчёт просит переснять.

## Pytest

```bash
venv/Scripts/python.exe -m pytest tests/golden/test_sety_reference.py              # без БД, секунды
SETY_GOLDEN=1 venv/Scripts/python.exe -m pytest tests/golden/test_sety_reference.py -m sety_golden  # пересчёт, ~10 мин
```

Без `SETY_GOLDEN=1` тест с маркером `sety_golden` пропускается. Он запускает `check` по всем
случаям, у которых есть снятый эталон, и требует код 0.

## Зонды (проверка ревью на данных)

`check --probe <зонд>[,<зонд>]` запускает sety через `sety_probe.py` с подменами функций — код
sety не меняется. Наблюдения пишутся в `meta.json` → `probe`.

| зонд | что делает | пункт ревью |
|---|---|---|
| count | считает вызовы getF1/getE1, drvary5, запасной регуляризации нагрузок, норм = 300 и нули, отброшенные read_row | 2.1, 2.6, 2.7, 2.8, 2.12 |
| teplo_iters | итерации calc_teplo и последняя Δt | 2.13 |
| keep_zeros | read_row/read_row2 сохраняют числовые нули | 2.1 |
| kv1 | незаполненный коэффициент вариации = 1 | 2.2 |
| no_podpitka_t | без «поправки на подпитку» температуры в us_out | 2.3 |
| diag_reg_off | тепловой расчёт без DIAG_REG = 1e-6 на каждой диагонали | 2.12 |
| nagr_reg_off | запасная регуляризация нагрузок без добавки к каждой строке | 2.12 |

`--set поле=значение` меняет параметр случая (поле `SetyRunRequest`), например `--set trtp=1`.
Эталон снимается только без зондов и без `--set`. Итоги проверки — `docs/sety-review-section2-check.md`.

## Астана: копия базы

Рабочие базы Астаны (`astanagid_2026_09_22`, `astana`) только для чтения, а расчёт пишет в
`calculation` и `*_out`. Поэтому 29.10.2026 сделана копия `astanagid_copy` — дамп
`H:\tgid-backups\astanagid_2026_09_22_20261029.dump` (1,2 ГБ, восстановление около 2 мин).
Пересоздать её из свежей базы:

```bash
pg_dump -h 127.0.0.1 -p 5440 -U postgres -Fc -f H:\tgid-backups\astanagid_2026_09_22.dump astanagid_2026_09_22
dropdb -h 127.0.0.1 -p 5440 -U postgres astanagid_copy
createdb -h 127.0.0.1 -p 5440 -U postgres -T template0 astanagid_copy
pg_restore -h 127.0.0.1 -p 5440 -U postgres -d astanagid_copy --no-owner -j 4 H:\tgid-backups\astanagid_2026_09_22.dump
```

После этого эталон нужно снять заново: `run_reference.py capture --cases astana_plan_tg`.
`CREATE DATABASE … TEMPLATE astanagid_2026_09_22` не подойдёт: к базе стенда и прода всегда есть
подключения.

У потребителей Астаны не заданы коды удельных расходов, поэтому плановый расчёт без `-tg`
останавливается сообщением «Не задан Код удельных расходов в потребителе». Все расчёты Астаны
идут по температурному графику, и случай тоже: Tн −31,2, фрагмент 3179 «Магистрали 2026-2027
c приростом». Расчёт идёт около 5 мин, с прогревом — около 10.
