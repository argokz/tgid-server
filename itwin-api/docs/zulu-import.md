# Переход с ZuluGIS / ZuluThermo (фаза 5)

Окно «Фрагменты: экспорт, импорт, слияние» → вкладка «Из ZuluGIS»: слой тепловой сети Zulu становится фрагментом ТГИД.

## Как устроено

1. **Загрузка** — `POST /api/v1/zulu/upload`: все файлы папки слоя или их zip (`*.b00`–`*.b10`, `*.d*`, `*.l*`, `*.zsx`,
   `*.zx`, база `*.sqlite`). Сервер находит слой, считает объекты графического слоя по типам и строки баз слоя и кладёт
   файлы слоя в хранилище файлов (FILE_STORAGE) на срок фоновых файлов. В загрузке несколько слоёв — параметр `layer`.
2. **Конвертация** — `POST /api/v1/zulu/convert {upload_id, name, tn}`: фоновая задача file-jobs `zulu_convert`
   (воркер Celery). Конвертер десктопа (`zulu_converter/`, копия gid8 `python/zulu2`) работает отдельным процессом,
   свой TMP, предел `ZULU_TIMEOUT_S` (по умолчанию 1800 с). Результат — `.itwin` (несколько фрагментов — zip из `.itwin`),
   сводка — заголовок `X-Zulu-Report`. Статус и файл — общие `/api/v1/file-jobs/{id}` и `…/download`.
3. **Импорт** — веб подаёт файл на вкладку «Импорт» и сразу проверяет (`dry_run`): что создастся и где сеть ляжет на
   карте (`geometry.bbox_wgs84`). «Импортировать» создаёт фрагмент; отмена — «Отменить операцию».

Права — как у импорта фрагмента (импорт участков; применение — редактор топологии). Чужую загрузку конвертировать
нельзя; через общий `POST /api/v1/file-jobs` вид `zulu_convert` не запускается.

## Система координат

Конвертер переносит координаты слоя как есть (параметры проекции пишет в «Систему теплоснабжения» фрагмента для
десктопа). Если слой Zulu не в местной системе города — на вкладке указать его проекцию EPSG (свойства слоя в ZuluGIS):
импорт пересчитает геометрию в систему города (PostGIS `ST_Transform`) и перепишет `x/y` узлов и `coords` участков в её
единицах. Проверка импорта показывает охват сети в градусах — по нему видно, на месте ли сеть. Параметр `source_srid`
работает и для любых `.tgid`.

## Ограничения

- Нужна база слоя в SQLite; базы Paradox (`*.db`) старых версий Zulu не поддерживаются (нет `pypxlib`) — в ZuluGIS
  перевести базу слоя в SQLite.
- Загрузка — до 200 МБ, файл внутри zip — до 20 МБ.
- Что и как переносится (например, расход обобщённого потребителя `Gpod` — в его нагрузку с признаком задания
  расходом, имена ЦТП — в имена узлов) — решения конвертера десктопа; веб их не меняет.

## Попутная правка импорта .tgid

`coords` участка — числа подряд через пробел или запятую, парами x y (как читает десктоп, `CCoordList::loadStr`).
Раньше импорт понимал только «x y,» по одной точке и терял изломы трасс, записанных через пробел: на примере Zulu
изогнутыми выходили 10 участков из 39, теперь 39; длина по геометрии 13 469,7 м против 12 621,8 (по паспорту 13 573,8).

## Проверка (пример ZuluGIS `Examples\Thermo\Magistral\Teplo`, копия Алматы)

- Слой: 77 участков, 59 узлов, 15 обобщённых потребителей, 1 источник; в базах слоя ещё 65 строк удалённых объектов.
- Конвертация воркером — 63 с; фрагмент: 75 узлов (59 + 15 + 1), 77 участков, источник, 15 обобщённых потребителей,
  узел заданного напора; длина по паспорту 13 573,8 м = сумма `L` участков слоя.
- Импорт применён и отменён; с `source_srid` расхождение `x/y` и геометрии — 0.

## Выкатка

Новых пакетов и таблиц нет (`networkx`, `pyodbc` уже в requirements). Перезапустить API и воркер Celery (новый вид
фоновой задачи). Нужны Redis/хранилище фоновых файлов, как для остальных фоновых выгрузок.
