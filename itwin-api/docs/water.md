# Водопровод: модели EPANET и расчётный движок

Фаза 4 модернизации («мультисетевая ГИС»), шаг 1: водоканал в той же системе — модель сети, расчёт, сеть на карте.

## Устройство

- **Расчётный движок** — отдельная служба `water_engine/` со своей средой (`water_engine/requirements-water.txt`:
  WNTR 1.5.0, FastAPI, uvicorn). WNTR (Sandia National Laboratories, лицензия BSD) читает модели EPANET (.inp) и
  считает их встроенным EPANET 2.2. API ТГИД не тянет numpy / scipy / pandas и WNTR — обращается к движку по HTTP.
- **ТГИД** (`database/water.py`, `routers/water.py`) хранит в базе города модель (текст .inp — из него считает
  движок), узлы и участки на карте (`tgid_water_node` / `tgid_water_link`, 4326) и расчёты (`tgid_water_run`:
  сводка и значения по шагам). Миграция `20261101_water.sql`, API накатывает сам.
- **Веб** — «Инструменты → Водопровод: расчёт сети» (`WaterDialog.vue`): модели, загрузка учебной сети, расчёт
  суток, сводка, сеть на карте (узлы — по давлению, трубы — по скорости) и перемотка по часам. Геометрия грузится
  один раз, при перемотке — только значения шага.

Запуск движка (служба Windows — через NSSM, как службы API):

    python -m venv water-venv
    water-venv\Scripts\pip install -r water_engine\requirements-water.txt
    set WATER_ENGINE_TOKEN=<секрет>
    water-venv\Scripts\python -m uvicorn --app-dir <itwin-api> water_engine.service:app --host 127.0.0.1 --port 8070

API: `WATER_ENGINE_URL` (по умолчанию `http://127.0.0.1:8070`) и тот же `WATER_ENGINE_TOKEN`. Движок недоступен —
модели видны, расчёт не запускается (окно предупреждает).

## Модели и привязка к карте

- **Учебные сети** идут с WNTR: Net1, Net2, Net3, Net6 (EPANET), ky4, ky10 (Кентукки). Координаты в них условные —
  сеть размещается **схемой** у центра города (центр источников тепла, или `WATER_ORIGIN_LAT` / `WATER_ORIGIN_LON`),
  размер — по числу узлов (150 м × √узлов, от 1 до 15 км). Это схема для работы с расчётом, а не трассы.
- **Своя сеть водоканала** — `POST /api/v1/water/models/upload` (файл .inp, `srid` — система координат файла):
  координаты переводятся в 4326 PostGIS.

## Расчёт

`POST /api/v1/water/models/{id}/runs` (право «Расчёт»): гидравлика EPANET по периоду (по умолчанию — сутки, шаг
отчёта — час). Единицы ответа — СИ (модели в американских единицах WNTR переводит): давление и напор — м, расход —
л/с, скорость — м/с, удельные потери — м/км. Сводка: давление мин…макс, узлы с давлением ниже 10 м и отрицательным,
трубы со скоростью выше 2 м/с.

Стенд (копия Алматы):

| Сеть | Узлы / участки | Загрузка | Расчёт суток | Давление, м | Ниже 10 м | Отрицательное | Скорость > 2 м/с |
|---|---|---|---|---|---|---|---|
| Net3 | 97 / 119 | 1,0 с | 1,0 с | −0,6…93,4 | 4 | 1 (узел 10 у насосной) | 1 |
| Net6 | 3356 / 3892 | 2,8 с | 5,9 с | 0,1…231 | 35 | 0 | 6 |

Шаг Net6 целиком с геометрией — 1,65 МБ, поэтому перемотка запрашивает только значения шага
(`/runs/{run}/step`).

## Адреса API

| Адрес | Кто | Что |
|---|---|---|
| `GET /api/v1/water/status` | вошедший | доступен ли движок, версия WNTR |
| `GET /api/v1/water/library` | вошедший | учебные сети движка |
| `GET /api/v1/water/models` | вошедший | модели города |
| `POST /api/v1/water/models` | право «Справочники» | загрузить учебную сеть `{library}` |
| `POST /api/v1/water/models/upload` | право «Справочники» | загрузить .inp (`srid` — СК файла) |
| `DELETE /api/v1/water/models/{id}` | право «Справочники» | удалить модель с сетью и расчётами |
| `POST /api/v1/water/models/{id}/runs` | право «Расчёт» | расчёт (`duration_h`, `report_step_h`) |
| `GET /api/v1/water/models/{id}/runs` | вошедший | расчёты модели |
| `GET /api/v1/water/models/{id}/geojson` | вошедший | сеть для карты (`run_id`, `step` — со значениями) |
| `GET /api/v1/water/models/{id}/runs/{run}/step` | вошедший | значения шага без геометрии |
